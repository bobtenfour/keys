# Project Governance

## Authority
This document governs project-level decision discipline.

## Purpose
Define non-negotiable project rules that protect the system from technical debt and architectural drift.

## Governing Principles
- Architecture first.
- Contracts first.
- Implementation after validation.
- One source of truth.
- One authority per decision.
- One slice at a time.
- No patches.
- No shortcuts.
- No hidden assumptions.
- No framework-default product experience.

## Conflict Rule
If documents conflict, implementation stops until the contradiction is resolved. No developer or AI may choose a convenient interpretation.

## Change Rule
A governing document may change only when the change removes ambiguity, eliminates duplicate authority, or establishes a required architectural boundary.
